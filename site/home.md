## The Safe Loop

| # | Step | What you do |
|---|---|---|
| 1 | **Describe** | Goal, context, constraints, "done when". Write the check first |
| 2 | **Plan** | Ask for a plan, and edit it before any code is written |
| 3 | **Step** | One small change at a time |
| 4 | **Test** | Run your check, the normal case and an edge case |
| 5 | **Read** | Read the diff, and write a short teach-back of what changed and why |
| 6 | **Commit** | A git save point with a clear message |

If two fixes in a row fail, stop, start a fresh chat and rewrite the prompt: the **two-strikes rule**. [Printable card](/resources/safe-loop).

## How to use this site

- **Students:** start with the [first-hour quick start](/setup/#before-studio-1) before Studio 1. Each week, open the week's overview and read **This week at a glance** first: it lists what to do before Studio A, what each studio covers, what's due and the minimum to keep up. Keep [troubleshooting](/resources/troubleshooting) and the [glossary](/resources/glossary) handy.
- **Self-paced learners:** follow the [self-paced path](/resources/self-paced), which says what replaces each studio activity when you're working alone. When you're stuck, use [tutor mode](/resources/tutor-mode).
- **Screen reader or keyboard users:** the [accessibility guide](/resources/accessibility) covers every tool the course uses.
- **Instructors:** instructor notes, answer keys and the instructor guide are in the [GitHub repository](https://github.com/Boyu-Zhang-UOI/Vibe_Coding_101).
